STEP 6: Speed optimization (later undone in Step 13)
-------------------------------------------------------------------------------
Asked:    Suggest ways to make the layers load faster, then "do what you think will make
          things optimized the quickest". Make a .tar.gz backup first, and delete the extra
          2 GB GeoJSON.

Done:
  - chunkedAreaLayer.js was rewritten to draw one batched GroundPrimitive per chunk instead of

    antialiasing on large screens.

STEP 11: Voice said public housing and life expectancy were "not supported"
-------------------------------------------------------------------------------
Causes:   (1) Public housing, trauma centers and GVA weren't on voice's list.
          (2) Voice's instructions never said how to answer questions about these layers.
          (3) Answers asked right after a fly-to were read at the old location.
Code:
  - server/providers/openai/instructions.js: a new rule that these layers are supported, with
    the steps: turn the layer on, fly to the place and wait, then call get_entity_context.
  - Pin layers gained getAreaContext (nearest sites with distances, the count within 5 km, and
    the legend).
  - Area layers gained getAreaContext (the area under the point, its neighbors, and the
    legend). It forces a reload for the current view and waits up to 6 seconds.
  - gevActions.js:
      - waitForCameraFlight(), so answers wait for the camera to land.
      - areaLayerContexts(), which runs every enabled layer's getAreaContext.
      - If the screen-center pick is implausibly far away, it uses the ground under the
        camera instead.
  - Verified: after flying from Chicago to Roxbury, voice read tract life expectancy, public
    housing within 5 km and the nearest trauma center.

STEP 14: GitHub push errors
-------------------------------------------------------------------------------
Problems and fixes:
  - origin pointed to github.com/nu_stats/... (underscore), but the account is "nu-stats"
    (hyphen), and GitHub usernames can't contain underscores.
  - The GitHub repo was created as "-husky-eye-view", with a leading hyphen. Pointing git at
    "husky-eye-view" (no hyphen) gave "repository not found" because that repo doesn't exist.
  - Fix: `git remote set-url origin https://github.com/nu-stats/-husky-eye-view.git`.
  - Safety checks before pushing to the public repo: no API keys are in any commit (the
    "sk-..." matches are upstream placeholders), and no file is over GitHub's 100 MB limit.
    The repo is public, so the exported datasets (including MKDB) are public too.
